# $.py — build spec

For: Greenlee County, Arizona

This file is not auto-generated — too much of it depends on how this
county's specific property-assessor website is built. Use this doc (plus
your own look at the live site in dev tools) to write it from scratch.

## Where this fits in the pipeline

`master.py` runs four scripts in order: `obi.py` → `$.py` → `DC.py` →
`pricer.py`. `obi.py` has already scraped recent obituary names into a
shared local cache (`pipeline_cache.db`, managed by `pipeline_db.py`). This
script's job: for every one of those names, search the county assessor
site by last name, and record any owner record that plausibly matches as a
candidate match, with that property's parcel id, address, city, state, zip.

`DC.py` runs after this and doesn't need any changes — it confirms
candidates by cross-checking Legacy.com obituary text, independent of
whatever this county's assessor site looks like.

## File name and location

Must be saved as exactly `$.py` (the dollar sign matters — `master.py`
looks for that literal filename) in this same folder, alongside
`pipeline_db.py`, `geocode.py`, `DC.py`, `pricer.py`, `master.py`.

## What's already built for you — don't reinvent these

- `pipeline_db.get_obituary_names_with_dates()` → list of
  `(full_name, posted_date)` tuples, already scraped by `obi.py`.
- `pipeline_db.clear_matches()` → call once at the very start of the run,
  before searching anyone. Wipes stale matches left over from the last run.
- `pipeline_db.add_match(full_name, owner_name, parcel_id, address, city, state, zip_code, posted_date)`
  → call this for every match found. This is the only output this script
  needs to produce — no Excel file, no return value. `DC.py` reads straight
  out of `pipeline_db` afterward.
- `geocode.geocode_address(driver, street_address, city=None)` → returns
  `(city, state, zip_code)` by searching the address on Google, using the
  Selenium `driver` you pass it. Reuse the same browser you're already
  searching the assessor site with — don't spin up a second one just for
  this call.
  - **Important gotcha:** this call navigates that same `driver` away to
    Google. Anything you still need off the assessor's results page (owner
    name, parcel id, address for *other* rows on the same page) must be
    read out as plain text *before* you call this for any one match —
    otherwise you'll get stale-element errors on the rows you haven't
    processed yet.

## Matching heuristic — follow this, the rest of the pipeline expects it

- Split the deceased's full name into `last_name` and `first_name`.
  Handle "Jr."/"Sr." suffixes (skip them, use the word before) and
  parenthetical nicknames like `"Jacob (Jake) Smith"` (strip the
  parenthetical before splitting).
- Search the assessor site by `last_name`.
- A candidate counts as a match if **any word in the owner-record name
  starts with `first_name`** (case-insensitive). Deliberately loose —
  assessor "owner name" fields are often formatted like
  `"SMITH, JACOB G; TR"`, not a clean "First Last". Don't require an exact
  match.
- Non-matches are simply skipped, not recorded.

## Cases to handle

Inspect the live site yourself to know which of these actually apply — not
every county's site behaves the same way:

1. **No results** for a last name → move on to the next name.
2. **Single result redirects straight to a "parcel details" page** (a
   single-record layout, not a list). If this county's site does this,
   you'll need to pull owner/parcel/address from that page's specific
   layout. If it *never* does this — every search, even a single match,
   just shows as a one-row list — skip this case entirely and always use
   case 3 below.
3. **Multiple results shown as a list/table.** Extract owner name, parcel
   id, and address per row. Grab everything as plain text up front — see
   the geocode gotcha above.

## General guardrails

- Use Selenium, consistent with the rest of this pipeline. Plain
  `webdriver.Chrome` + `webdriver_manager` is fine unless this specific
  site triggers bot-detection/CAPTCHAs, in which case switch to
  `undetected_chromedriver` the same way `DC.py` already does (copy its
  `detect_chrome_major_version()` + `uc.Chrome(...)` pattern if needed).
- Wrap each name's search in try/except — one broken lookup shouldn't kill
  the whole run. Log the error, move to the next name.
- Print a line per name searched and per match found — plain console
  output, no logging framework, consistent with the rest of the pipeline.
- Don't guess selectors from Salt Lake County's old version of this file —
  every assessor site's DOM is different. Look at the real thing.
